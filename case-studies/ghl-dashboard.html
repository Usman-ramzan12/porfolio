GoHighLevel Growth &
Attribution Dashboard

Live KPI dashboard for a US medical-aesthetics growth agency — pulling real-time data from the GoHighLevel v2 API with a Node.js serverless backend on Vercel, timezone-aware reporting, and silent bug fixes for under-counting.

Role: Sole Developer · Client: US medical-aesthetics growth agency (private) · Built at: NDT Group
Stack
Node.jsVercel ServerlessGoHighLevel API v2Tailwind CSSChart.jsREST
The Problem

The agency had data — but no visibility

A US medical-aesthetics growth agency was managing hundreds of leads and appointments through GoHighLevel but had no consolidated view of their funnel performance. They needed real-time visibility into Speed to Lead, booking rates, show-up rates, rep performance, and attribution — all from a single dashboard.

The hidden complexity: the GHL v2 API doesn't paginate correctly for large date ranges, silently drops records when over the page limit, and stores all timestamps in UTC while the business operates across multiple timezones — one of which had an off-by-one bug in date-range handling.

My Approach

Serverless API layer + bento card UI

1

Node.js serverless functions on Vercel

Separate endpoints for each dashboard view: overview, conversion funnel, daily appointments, attribution, deals by rep, recent closes, and pipeline status. Each endpoint fetches, filters, and aggregates GHL data server-side before sending it to the UI.

2

Cursor-based pagination with early exit

GHL's API silently drops records on large result sets. Implemented cursor-based pagination with an early exit once records pass the requested date range — guaranteeing complete data without over-fetching.

3

Timezone-aware reporting

Each GHL location stores its own timezone. I fetch and cache the timezone per location (with a UTC fallback), then convert all timestamps before grouping by date — fixing an off-by-one bug where appointments were attributed to the wrong day.

4

Strict lead definition + deduplication

Enforced a business rule: a contact counts as a lead only if they have a name, email and phone number. Added deduplication to prevent the same contact appearing in multiple funnels.

Hard Problems Solved

The silent bugs that skewed reporting

Silent under-counting from API pagination

The GHL v2 API uses offset-based pagination internally and will silently truncate results when a query spans a large date range. Without cursor-based pagination and an explicit early-exit check, dashboards that look correct on small date ranges will under-report on weekly or monthly views — and the client would never know.

Timezone off-by-one in date-range attribution

GHL returns timestamps in UTC. When grouping appointments by day for a location in US Eastern time, an appointment at 11pm UTC on Monday is actually 6pm Monday Eastern — but without timezone conversion it lands on Tuesday in the reporting. Fixing this required reading each location's timezone from the API, caching it, and converting before any date arithmetic.

Duplicate contacts inflating funnel counts

GHL creates a new contact record every time a lead comes in through a different channel, meaning the same person could appear in the funnel multiple times. Added deduplication on email + phone before counting, with the business-rule filter (name + email + phone all required) to distinguish real leads from partial form fills.
